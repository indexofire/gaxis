# 03 Template Adaptation: Change the Data, Not the Code

## Goal

Reuse one piece of **verified** plotting code (a template) and bind it only to your data: data path, output directory, delimiter, column mapping.
Don't reinvent the styling, and don't let the code and data quietly drift apart.

## Prerequisite: Templates in the KB

```bash
pixi run gaxis kb seed --preset asm --backend python
pixi run gaxis kb status
```

`kb seed` performs a real render for every (preset × chart × backend) pair; anything that fails lint is not admitted into the KB. Template pages are
`type: template`, with `code_path`, `code_sha256`, `interface: full`.

Idempotent: repeated runs only skip unchanged items.

```bash
pixi run gaxis kb seed --preset asm --backend python
# templates: 0 written, 6 unchanged, 0 failed
```

## Your First Adaptation

```bash
pixi run gaxis adapt --data examples/demo/expr.tsv --preset asm --query "bar chart"
```

```
source:  kb_asset
asset:   template:asm-bar-python
figure:  bar-43e3d19d74
code:    /…/data/renders/bar-43e3d19d74/figure.py
wrote:   …/bar-43e3d19d74.pdf
lint: clean
```

`source: kb_asset` means the code came from a knowledge-base asset; `asset_ids` records the specific template; the same is written to the manifest.

## What It Actually Changes

Adaptation rewrites only the constants a human would change; the plotting code is left untouched:

| Constant | Python | R |
|---|---|---|
| Data path | `DATA_PATH = Path(...)` | `DATA_PATH <- "..."` |
| Output directory | `OUT_DIR = Path(...)` | `OUT_DIR <- "..."` |
| Filename stem | `STEM = "..."` | `STEM <- "..."` |
| Delimiter | `DELIMITER = "\t"` | `SEP <- "\t"` |
| Encoding intent | `SPEC = {...}` | `SPEC <- list(...)` |

Every replacement is validated: if the template structure doesn't match (e.g., missing `DATA_PATH`), it reports `adaptation_failed` instead of running the wrong code.

## What If Column Names Differ

`--query` decides the chart type, but the column names come from your data. Adaptation writes `SPEC` with your column names:

```bash
# your table: strain, group, value
pixi run gaxis adapt --data my.csv --preset asm --query "bar chart"
```

In the generated `figure.py`, `SPEC` will be `strain/group/value`, and the template's statistics and styling logic stay unchanged.
If the template's chart type doesn't suit your data (e.g., it expects a heatmap but you only have two numeric columns), `infer_spec` picks an encoding that can run,
and the artifacts tell you the result; when it can't fit, it fails explicitly rather than silently.

## Dry Run and Code Review

```bash
pixi run gaxis adapt --data my.csv --preset asm --query "bar chart" --dry-run
```

It writes only the script and manifest, without executing. Good for reviewing the diff first:

```bash
diff data/assets/templates/asm/bar-python/figure.py data/renders/<id>/figure.py
```

You'll see that only the constants block differs.

## Switching Backends

```bash
pixi run gaxis adapt --data my.csv --preset asm --backend r --query "bar chart"
```

R templates likewise change only the bindings; the plotting part is ggplot2.

## What Happens When a Template Is Missing

```bash
pixi run gaxis adapt --data my.csv --preset nature --query "bar chart"
```

```
source:  builtin_templates
fallback: no verified template for preset=nature chart=bar backend=python; run `gaxis kb seed`
```

This is an **explicit fallback**: it still produces a figure, but clearly tells you that no KB template was used. To fill in the missing template:

```bash
pixi run gaxis kb seed --preset nature
```

## Checkpoints

- [ ] `source: kb_asset`, `asset_ids` non-empty;
- [ ] The generated script changes only the constants block, and the plotting code matches the template;
- [ ] `manifest.asset_ids` matches the terminal output;
- [ ] `data/kb/selections.jsonl` contains an `action: adapt` record.

## Common Issues

**`no verified template ... run gaxis kb seed`**: there is no template for that preset/chart/backend. Seed first.

**`adaptation_failed: template is missing ...`**: the asset is not a template generated by gaxis (e.g., a script placed into the KB by hand).
Use `kb adopt` to go through the paper-code channel (next section), or `kb seed --force` to rebuild it as a template.

**The figure is wrong after adaptation**: first `diff` the template against the artifact; then check whether the column names in `SPEC` actually exist. Adaptation doesn't understand business semantics;
it only guarantees that the bindings are correct.
